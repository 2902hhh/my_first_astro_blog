# 本地写作

Windows 本地应用，为现有 Astro 博客提供草稿管理、可视化写作和图片处理。沿用博客的蓝紫青色 Aurora 风格和系统中文字体。

## 双击使用

构建完成后双击 `out/LocalWriting-win32-x64/本地写作.exe`。整个输出文件夹需保留在一起。首次打开选择博客 Git 项目的根目录，目录应包含 `astro.config.mjs`、`src/pages/posts/` 和 `public/images/`。

首次发布需要这台电脑已有 Git、可用的 GitHub 登录，以及博客项目的 Node.js 依赖。应用使用本机 Git 的认证，不存储 GitHub 密码或令牌。现有托管平台应继续通过 GitHub `main` 分支部署；应用推送成功并不等于部署已完成。

## 写作

- 点击“新建文章”；填写标题、正文、分类和标签。摘要可以留空，博客继续从正文开头截取作者原文，不生成文字。
- 草稿输入后自动保存，也可点击“保存”或按 `Ctrl+S`。切换文章和关闭窗口前等待保存完成；保存失败时保留当前编辑器，便于重试。
- “已公开”列表可打开现有文章；修改先保存在本机编辑草稿，公开版本在发布前保持原状。已有地址锁定，文章的自定义元数据保留。打开或只保存草稿不会修改文章源文件。
- 默认可视化编辑；正文上方可切换 Markdown 模式。支持标题、列表、代码、表格和公式。原有 HTML 图片在可视化模式下显示为图片，并在保存时恢复原有 HTML 属性；源码模式保留原始写法。
- 拖入、粘贴或选择 PNG、JPEG、WebP、GIF 图片。点击正文图片或右侧缩略图，用滑块或百分比设置显示宽度（10%–100%）；只影响该处图片。说明文字由作者填写。
- 本机静态图片支持自由裁剪及 1:1、16:9、4:3 比例。可拖动选区，也可用坐标输入和键盘调整。裁剪输出 PNG 副本并按原始图像分辨率导出，原图保留。外部链接图片与 GIF 不裁剪，可先在本机保存静态图片后插入。
- 预览展示文章正文、图片和数学公式；导出 Markdown 不自动打包图片，图片仍引用博客路径。

## 发布和撤回

“公开发布”会先展示具体标题、地址、分类与目标 GitHub 仓库。确认后检查仓库、构建 Astro，再只提交本篇文章和正文引用的新图片，推送到 `origin/main`。草稿和未引用图片不会进入仓库。博客项目有其他未提交更改，或本地与远端版本不一致时，应用会停止发布，保留内容；同步仓库后可重试。

构建失败会恢复本次修改的文件。提交后推送失败时保留本机提交与发布记录，点击“重试推送”即可继续，不重复提交。发布中断时应用保留恢复记录，并在下一次启动检查恢复；发现外部修改时停止覆盖并提示检查。

“撤回公开”从网站移除文章并保留本机草稿。已公开过的文章、图片仍可能保留在 GitHub 历史和已有缓存中。删除本机编辑草稿不会删除公开文章。

草稿和原始图片保存在 Windows `%APPDATA%` 下的应用数据目录，按博客项目隔离；具体草稿路径可查看界面中“选择博客项目”下方路径的提示。复制项目到其他目录会使用不同的草稿库。备份或迁移应用时需保留应用数据目录。

从“丁焕写作”升级时，应用继续使用已有的数据目录，保留草稿、图片和博客连接设置。

## 开发与检查

在博客根目录运行：

```sh
npm ci --prefix studio
npm run studio         # 构建并运行 Electron
npm run test:studio    # 使用临时仓库测试，不触碰真实 GitHub
npm run studio:package # 生成 Windows x64 应用文件夹
npm test               # 验证原博客的构建与阅读功能
```

`node studio/scripts/preview.mjs` 是开发时的隔离界面验证服务，仅监听 `127.0.0.1:4335`。它复制博客到 `studio/.test-data/`，使用本地裸仓库作为远端，不连接真实 GitHub。先运行 `npm run build --prefix studio`；验证期间不要把它当作正式写作应用。

主进程使用限定的 IPC 接口处理文件与 Git；渲染进程禁用 Node 集成、启用上下文隔离和沙箱，文章预览经过编辑器的 HTML 清理。编辑器、中文语言资源、代码高亮和公式资源随应用打包，日常离线写作无需 CDN。外部图片仍需网络。
